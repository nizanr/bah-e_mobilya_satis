# İş planı

Önerideki temel rol dağılımı korunmuştur: Nisa backend/veritabanı; Zeynep frontend/UX/3D. Rapordaki zaman çizelgesinde çelişen sorumlu satırları bu dağılıma göre düzenlendi. Haftalar ders başlangıcına göredir; kesin takvim öğretim elemanı ile eşleştirilmelidir.

| Paket | Hafta | İş                                                    | Sorumlu            | Teslim / kabul                                          |
| ----- | ----- | ----------------------------------------------------- | ------------------ | ------------------------------------------------------- |
| WP1   | 1     | Gereksinimler, rol matrisi, ödeme ve özgünlük kapsamı | Ortak              | Gereksinim listesi, sunum 1                             |
| WP2   | 1–2   | MongoDB şeması ve Express API                         | Nisa               | Kullanıcı, ürün, sipariş, tasarım koleksiyonları        |
| WP3   | 2–3   | Üyelik, oturum ve sunucu taraflı yetkilendirme        | Nisa               | Yetkisiz işlem testleri; sunum 2 / canlı kodlama        |
| WP4   | 2–4   | Responsive katalog ve kullanıcı arayüzü               | Zeynep             | Arama, kategori, ürün detayı, mobil görünüm             |
| WP5   | 4–5   | Sepet, stok, sipariş ve iyzico test ödeme             | Nisa               | Sağlayıcıyla doğrulanmış test ödeme ve iptal politikası |
| WP6   | 5–6   | Fotoğraf üzerinde 3D stüdyo                           | Zeynep             | Fotoğraf yükleme, sürükleme, boyut, dönüş, kaydetme     |
| WP7   | 6–7   | Bağımsız test ekibi ve hata yönetimi                  | Ortak + test ekibi | Gerçek bulguların raporları, tekrar test sonuçları      |
| WP8   | 8     | Kod inceleme, performans, dağıtım ve teslim           | Ortak              | Sunum 3, demo, README, teslim etiketi                   |

6 Ekim GitHub koşulu geçmiş bir ders teslim koşuludur: yerel dosyaların hazırlanması, GitHub'a yükleme yapıldığı anlamına gelmez. Bu çalışma otomatik push yapmaz. Depo commit/push tarihlerini öğretim elemanının ilgili dönem takvimiyle kontrol edin.

100 hata koşulu, 100 test senaryosuyla eşdeğer değildir. Test ekibi yalnızca gözlemlediği gerçek hataları raporlamalıdır; tekrarları ayrı hata gibi göstermemelidir. Yeterli bulgu yoksa koşulun yorumunu öğretim elemanı ile netleştirin.
